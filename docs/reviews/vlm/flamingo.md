## 핵심 아이디어

Flamingo가 목표로 삼은 것은 **멀티모달 영역에서의 few-shot learning**이다. 소수의 예시만 프롬프트에 넣어주면 새로운 태스크에 즉시 적응하는, [GPT-3](../llm/gpt3.md)가 언어에서 보여준 능력을 시각-언어로 옮기는 것이다.

당시 vision-language 모델의 표준은 **태스크마다 수천 수만 개의 라벨로 fine-tuning하는 것**이었다. 태스크가 바뀌면 데이터를 새로 모으고 다시 학습해야 하므로, 새로운 문제에 빠르게 적응한다는 의미의 일반성과는 거리가 멀었다.

이를 해결하기 위해 Flamingo는 세 가지 문제를 동시에 풀어야 했다.

* **강력한 단일 모달 모델을 잇는 문제** — 이미 잘 학습된 vision 모델과 language 모델을 어떻게 결합할 것인가
* **임의로 교차 배열된 시퀀스를 다루는 문제** — few-shot 프롬프트는 본질적으로 `이미지-텍스트-이미지-텍스트...`의 나열이므로, 이런 **interleaved 형태를 처리할 수 있어야 한다**
* **이미지와 비디오를 모두 받는 문제** — 입력의 시각 토큰 수가 가변적인 상황을 처리해야 한다

Flamingo의 핵심 통찰은 **few-shot 능력이 모델 구조뿐 아니라 학습 데이터의 형태에서 나온다**는 점이다. 여러 개의 image-text 쌍이 하나의 시퀀스 안에 뒤섞인 **interleaved 웹 데이터(M3W)** 로 학습해야, 모델이 "예시들을 보고 패턴을 파악한다"는 것 자체를 배울 수 있다. 이는 훗날 [BLIP-2](blip2.md)가 쌍 하나짜리 데이터만 써서 in-context learning에 실패한 것과 정확히 대비된다.

그 결과 단 하나의 Flamingo 모델이 **16개 벤치마크에서 few-shot SOTA**를 달성했고, 그중 **6개에서는 태스크별 데이터로 fine-tuning된 SOTA 모델마저 32개 예시만으로 능가**했다.

## 방법론

### 전체 구조

<!--Figure: Figure 3 (Flamingo architecture overview)-->

Flamingo는 **frozen 상태의 vision 인코더와 언어 모델 사이에, 새로 학습되는 모듈들을 삽입**하는 구조이다.

- **Vision Encoder**: contrastive 방식으로 사전 학습된 **NFNet-F6**. 학습 후 **frozen**으로 고정한다. 출력은 2D 공간 격자를 1D로 펼친 형태이며, **비디오는 1 FPS로 샘플링**해 프레임별로 인코딩한 뒤 학습된 temporal embedding을 더해 1D로 펼친다.
- **Perceiver Resampler**: 가변 길이의 시공간 시각 feature를 **고정된 64개의 visual token**으로 변환한다.
- **Frozen LLM**: **Chinchilla** 계열(1.4B / 7B / 70B)을 사용하며 **frozen**으로 고정한다. Flamingo-3B, 9B, 80B가 여기서 나온다. 80B는 **Chinchilla 70B + 새로 학습되는 10B 파라미터**를 뜻한다.
- **GATED XATTN-DENSE**: frozen LLM 레이어 사이사이에 새로 삽입되는 cross-attention 레이어로, 언어 토큰이 시각 토큰을 참조하게 한다.

<br/>

### Perceiver Resampler

<!--Figure: Figure 5 (Perceiver Resampler module)-->

입력 이미지의 해상도나 비디오의 프레임 수에 따라 시각 feature의 개수는 달라진다. Perceiver Resampler는 **학습 가능한 latent query 집합**이 이 가변 길이 feature에 cross-attention하도록 하여, 언제나 **64개의 고정된 토큰**을 출력한다.

이 설계의 목적은 두 가지이다. 하나는 뒤따르는 vision-text cross-attention의 **연산 복잡도를 입력 크기와 무관하게 고정**하는 것이고, 다른 하나는 이미지든 비디오든 **동일한 인터페이스로 다루는** 것이다.

> **참고 — Q-Former의 선행 형태**: 학습 가능한 query가 가변 길이 시각 feature에 cross-attention하여 고정 개수의 토큰을 뽑아낸다는 발상은, 이후 [BLIP-2](blip2.md)의 Q-Former(32개 query)와 본질적으로 같다. 다만 Perceiver Resampler는 순수하게 **길이를 줄이는 압축 모듈**인 반면, Q-Former는 ITC·ITM·ITG로 **언어와의 정렬까지 사전 학습**한다는 점이 다르다.

<br/>

### GATED XATTN-DENSE와 tanh 게이팅

<!--Figure: Figure 4 (GATED XATTN-DENSE layers)-->

frozen LLM에 시각 정보를 주입하기 위해, 기존 레이어들 사이에 **새로 초기화된 cross-attention 레이어**를 끼워 넣는다. 삽입 빈도는 모델 크기에 따라 다른데, 3B는 매 레이어마다, 9B는 4개마다, 80B는 7개마다 넣는다.

문제는 **랜덤 초기화된 레이어를 중간에 끼워 넣으면 학습 초기에 frozen LLM의 출력을 망가뜨린다**는 것이다. Flamingo는 이를 **tanh 게이팅**으로 해결한다.

새로 추가된 레이어의 출력에 $\tanh(\alpha)$를 곱하는데, 여기서 $\alpha$는 레이어별로 학습되는 스칼라이며 **0으로 초기화**된다. $\tanh(0) = 0$이므로 **학습 시작 시점에 모델의 출력은 원본 LLM과 정확히 동일**하다. 학습이 진행되면서 $\alpha$가 서서히 커지며 시각 정보가 점진적으로 주입된다.

> **참고 — 항등 함수에서 출발하는 설계**: 새 모듈을 항등 함수(identity)로 초기화해 기존 모델을 건드리지 않고 시작하는 아이디어는 이후 여러 곳에서 반복된다. ControlNet의 zero-convolution, LoRA에서 한쪽 행렬을 0으로 초기화하는 방식이 같은 원리이다. **사전 학습된 능력을 훼손하지 않으면서 새 능력을 얹는 일반적 기법**으로 자리 잡았다.

ablation에서 tanh 게이팅을 제거하면 성능이 떨어질 뿐 아니라 **학습 자체가 불안정**해졌다.

<br/>

### Interleaved 시퀀스 처리와 마스킹

Flamingo가 few-shot 프롬프트를 다룰 수 있는 이유는 **interleaved 시퀀스를 위한 마스킹 설계**에 있다.

텍스트에는 이미지가 등장하는 위치를 표시하는 `<image>` 태그와 청크의 끝을 알리는 `<EOC>` 토큰이 삽입된다. 그리고 cross-attention에 다음과 같은 제약을 건다.

**각 텍스트 토큰은 자신의 바로 앞에 등장한 이미지 하나의 시각 토큰만 참조한다.** 이전에 나온 모든 이미지를 보지 않는다.

이 제약이 중요한 이유는 **일반화** 때문이다. 모델은 학습 중 시퀀스당 최대 5개의 이미지만 보지만, cross-attention이 항상 이미지 하나만 상대하므로 **추론 시에는 이미지 개수에 제약 없이 확장**할 수 있다. 실제로 32쌍까지 늘려도 동작한다.

그렇다고 이전 이미지의 정보가 사라지는 것은 아니다. **LLM 내부의 self-attention을 통해 이전 텍스트가 참조되고, 그 텍스트에는 이전 이미지의 정보가 이미 녹아 있으므로** 간접적인 의존성은 유지된다.

<br/>

### 학습 데이터

Flamingo는 **사람이나 기계가 주석을 단 데이터를 전혀 쓰지 않고**, 웹에서 수집한 네 종류의 데이터를 혼합해 학습한다.

- **M3W (MultiModal MassiveWeb)**: 4300만 개 웹페이지의 HTML DOM에서 **텍스트와 이미지가 교차 배열된 형태 그대로** 추출했다. 1억 8500만 장의 이미지와 182GB의 텍스트로 구성되며, 학습 시 256 토큰짜리 부분 시퀀스를 무작위로 뽑고 이미지는 최대 5개까지 취한다.
- **ALIGN**: alt-text가 붙은 18억 장의 이미지
- **LTIP (Long Text & Image Pairs)**: 더 긴 설명문이 붙은 3억 1200만 쌍
- **VTP (Video & Text Pairs)**: 평균 22초 길이의 짧은 비디오 2700만 개와 문장 설명

학습 목표는 시각 입력이 주어졌을 때 텍스트의 negative log-likelihood를 데이터셋별로 가중합한 것이다. 이때 데이터셋을 번갈아 가며 학습하는 round-robin 방식이 아니라 **모든 데이터셋에 대한 gradient를 누적**하는 방식이 결정적으로 중요했다.

<br/>

## 실험 결과

### Few-shot 성능

<!--Figure: Figure 2 (Flamingo results overview)-->

- **16개 멀티모달 벤치마크에서 few-shot SOTA**를 달성했다. 하나의 모델이 태스크별 학습 없이 프롬프트만 바꿔가며 얻은 결과이다.
- **그중 6개 태스크에서는 fine-tuning된 SOTA마저 능가**했다. 이때 Flamingo가 쓴 것은 **32개의 예시**뿐으로, 기존 모델들이 사용한 태스크별 데이터의 **약 1000분의 1** 수준이다.
- **shot 수와 모델 크기 모두에서 일관된 향상**이 나타났다. 예시를 늘릴수록, 모델이 클수록 성능이 좋아졌다.
- 추가로 fine-tuning까지 수행하면 **5개 태스크에서 새로운 SOTA**를 기록했다.

<br/>

### Ablation

<!--Figure: Table 3 (Ablation studies)-->

논문의 ablation은 어떤 설계가 실제로 기여했는지를 분명하게 보여준다.

- **Interleaved 데이터(M3W)가 가장 중요했다.** M3W를 제거하면 성능이 가장 큰 폭으로 하락했다. few-shot 능력이 아키텍처만으로 생기는 것이 아니라 **여러 예시가 한 시퀀스에 놓인 데이터를 학습해야 얻어진다**는 점을 뒷받침한다. 이미지-텍스트 쌍 데이터(ALIGN, LTIP)를 제거해도 상당한 하락이 있어, 데이터 혼합 자체가 중요했다.
- **LLM은 frozen이어야 한다.** 언어 모델을 처음부터 학습시키면 성능이 크게 떨어졌고, 사전 학습된 LLM을 **unfreeze해서 함께 학습시켜도 오히려 떨어졌다.** 원인은 **catastrophic forgetting**으로, 시각 데이터에 맞춰 갱신되는 과정에서 원래의 언어 능력이 훼손되기 때문이다.
- **tanh 게이팅 제거 시 성능 하락과 학습 불안정**이 함께 나타났다.
- **Perceiver Resampler**가 단순한 transformer나 MLP를 쓰는 것보다 좋았다.
- **gradient accumulation**이 round-robin 방식보다 우수했다.

<br/>

## 한계점

- **분류 태스크에서는 contrastive 모델에 뒤진다**: Flamingo는 생성 기반이라 범용성이 높지만, 순수한 이미지 분류나 검색에서는 [CLIP](clip.md) 같은 contrastive 모델보다 성능이 낮다. contrastive 모델은 애초에 image-text 유사도를 직접 최적화하도록 설계되었기 때문이다. **범용성과 태스크 특화 효율성의 트레이드오프**를 보여준다.
- **LLM의 약점을 그대로 상속**: hallucination, 근거 없는 추측, 학습 시보다 긴 시퀀스에 대한 일반화 부족 등 언어 모델의 고질적 문제가 그대로 나타난다.
- **프롬프트 설계에 대한 민감성**: in-context learning의 효과가 어떤 예시를 어떤 순서로 넣느냐에 크게 좌우된다. 성능이 프롬프트에 따라 흔들린다는 것은 실제 활용 시 **재현성과 안정성 측면의 부담**이 된다.
- **shot 수 증가에 따른 수익 체감**: 예시를 늘리면 성능이 오르지만 32개 부근에서 대체로 정체된다. 게다가 예시가 많아질수록 추론 시 시퀀스가 길어져 **연산 비용이 함께 증가**한다.
- **학습 파라미터가 여전히 크다**: frozen backbone을 쓰는데도 새로 학습되는 파라미터가 **102억 개**에 달한다. 이후 BLIP-2가 약 1.9억 개의 학습 파라미터로 zero-shot VQAv2에서 Flamingo-80B를 앞서면서, **frozen 활용의 효율을 더 끌어올릴 여지가 있었음**이 드러났다.
- **M3W가 비공개**: few-shot 능력의 핵심 재료인 interleaved 데이터셋이 공개되지 않았다. 모델 자체도 공개되지 않아, 커뮤니티가 이 결과를 재현하거나 발전시키기 어려웠다. **논문의 가장 중요한 기여가 가장 접근 불가능한 부분에 놓여 있는** 상황이었다.
- **웹 데이터에서 오는 편향과 유해성**: 필터링 없이 수집한 웹 데이터로 학습했으므로 사회적 편향과 유해한 출력의 위험을 안고 있다.

<br/>

## 인사이트

- **In-context learning은 데이터 형태가 만든다**: Flamingo가 남긴 가장 중요한 교훈이다. 여러 image-text 쌍이 한 시퀀스에 교차 배열된 데이터로 학습해야, 모델이 **"예시들로부터 패턴을 읽어내는 행위" 자체를 배운다.** 이 명제는 반대 방향에서 다시 확인되는데, BLIP-2는 쌍 하나짜리 데이터만 사용한 탓에 예시를 아무리 넣어줘도 성능이 오르지 않았고 논문 스스로 그 원인을 데이터 구조로 지목했다. **능력은 아키텍처가 아니라 학습 데이터의 구조에 새겨진다.**
- **frozen 전문가 + 학습 가능한 다리라는 원형**: 강력한 단일 모달 모델을 얼린 채 그 사이만 학습한다는 구성은 Flamingo가 먼저 제시했고, BLIP-2가 이를 훨씬 적은 파라미터로 다듬었으며, 이후 [LLaVA](llava.md) 계열이 연결자를 극단적으로 단순화하며 표준으로 굳혔다. **Flamingo는 이 계보의 출발점**이다.
- **항등 함수에서 출발하는 모듈 추가**: tanh 게이팅으로 $\alpha$를 0에서 시작하는 설계는, 사전 학습된 모델에 새 능력을 얹을 때의 일반 원리가 되었다. ControlNet의 zero-convolution, LoRA의 0 초기화가 같은 발상이며, **"기존 능력을 훼손하지 않는 것이 새 능력을 얻는 것보다 우선"** 이라는 관점을 담고 있다.
- **고정 길이 병목의 계보**: 가변 길이 시각 feature를 학습 가능한 query로 고정 개수 토큰으로 압축한다는 Perceiver Resampler의 발상은 Q-Former로 이어졌다. 입력 해상도나 프레임 수와 무관하게 **LLM이 받는 토큰 수를 통제한다**는 것은 지금도 유효한 설계 원칙이다.
- **frozen이어야 하는 이유는 효율이 아니라 보존**: LLM을 unfreeze했을 때 오히려 성능이 떨어진 결과는, frozen이 단순히 연산을 아끼는 선택이 아님을 보여준다. **강력한 사전 학습 능력은 건드리는 순간 손상되기 쉬우며**, 이 관찰은 BLIP-2의 2단계 학습 설계에서도 그대로 반복된다.
- **비공개가 낳은 오픈소스 생태계**: 모델과 M3W가 공개되지 않았다는 사실이 역설적으로 큰 파급을 낳았다. **OpenFlamingo**와 **IDEFICS** 같은 재현 프로젝트가 등장했고, interleaved 데이터의 부재를 메우기 위해 **MMC4**와 **OBELICS** 같은 공개 데이터셋이 구축되었다. 오늘날 멀티모달 모델들이 interleaved 데이터를 당연하게 활용할 수 있는 것은 이 과정을 거친 결과이다.
