## 핵심 아이디어

Qwen2.5-VL은 [Qwen2-VL](qwen2-vl.md)의 후속으로, **"이미지를 이해한다"에서 "이미지 위에서 정확히 지목하고 행동한다"로** 무게중심을 옮긴 모델이다.

Qwen2-VL이 해상도를 공간 축에서 해결했다면, Qwen2.5-VL은 그 발상을 **시간 축으로 확장**하고, 동시에 출력의 **정밀성과 구조화**에 집중한다. 네 갈래로 정리할 수 있다.

* **정밀한 grounding** — bounding box와 point를 **절대 좌표**로 표현해 객체의 실제 크기를 포착한다
* **문서 파싱** — 레이아웃 정보를 담는 **QwenVL HTML** 형식으로 문서 구조를 통째로 출력한다
* **긴 비디오 이해** — **동적 FPS 샘플링**과 **절대 시간에 정렬된 MRoPE**로 몇 시간짜리 영상에서 초 단위 사건을 짚어낸다
* **효율적인 ViT** — **window attention**을 도입해 연산량이 patch 수에 **선형**으로 증가하게 만든다

이 변화들의 공통 방향은 분명하다. **모델의 출력이 사람이 읽는 문장에서 기계가 파싱하는 구조로 바뀌고 있다.** 좌표, HTML, JSON, 타임스탬프는 모두 다음 단계로 넘겨질 수 있는 형식이며, 이는 VLM이 **에이전트의 부품**이 되어가고 있음을 뜻한다.

## 방법론

### 절대 좌표 기반 Grounding

<!--Figure: Figure (Object grounding with absolute coordinates)-->

기존 VLM들은 bounding box를 **정규화된 좌표**(0~1 범위)로 표현하는 것이 일반적이었다. 이미지 크기와 무관하게 일관된 표현을 얻을 수 있다는 장점 때문이다.

Qwen2.5-VL은 이를 **절대 좌표**로 바꾼다. 입력 이미지의 실제 픽셀 좌표를 그대로 사용하는 것이다.

이 변경이 의미를 갖는 이유는 **네이티브 동적 해상도와 맞물리기 때문**이다. Qwen2-VL 이후 모델은 이미지를 리사이즈하지 않고 원본 크기 그대로 받는다. 그렇다면 좌표도 원본 스케일로 다루는 것이 자연스럽고, 이때 모델은 **객체의 실제 크기를 인식**할 수 있게 된다. 정규화 좌표에서는 "이미지의 30%를 차지한다"까지만 알 수 있지만, 절대 좌표에서는 "가로 400픽셀짜리 객체"임을 안다.

또한 box뿐 아니라 **point 기반 grounding**을 지원하고, 탐지 결과를 **JSON 구조로 출력**한다.

> **참고 — 표현의 변경이 능력을 바꾼다**: 정규화 좌표에서 절대 좌표로의 전환은 코드 몇 줄 수준의 변경처럼 보이지만, **모델이 무엇을 알 수 있는지를 바꾼다.** 크기 정보가 표현에 담기지 않으면 모델은 그것을 학습할 수 없다. GUI 조작처럼 **실제 픽셀 위치를 클릭해야 하는 태스크**에서는 이 차이가 결정적이다.

<br/>

### QwenVL HTML: 문서를 구조로 출력하기

문서 이해의 결과물을 어떤 형식으로 낼 것인가는 생각보다 중요한 문제이다. 자연어 요약으로 내면 사람이 읽기는 좋지만 **레이아웃 정보가 사라진다.**

Qwen2.5-VL은 **HTML 기반의 문서 표현 형식**을 도입한다. 제목, 문단, 이미지, 표, 수식의 **위치 정보까지 함께** 담아 문서의 구조를 그대로 재현한다.

대상 범위도 넓다. 여러 장면과 여러 언어에 걸친 문서를 다루며, **손글씨, 표, 차트, 화학식, 악보**까지 포함한다.

<br/>

### 시간 축으로 확장된 동적 해상도

<!--Figure: Figure (Dynamic FPS sampling and absolute time alignment)-->

Qwen2-VL은 비디오를 **고정 2 FPS**로 샘플링했다. 이는 공간 축에서는 동적 해상도를 쓰면서 시간 축에서는 고정 방식을 유지한 셈이다. Qwen2.5-VL은 이 비대칭을 해소한다.

**동적 FPS 샘플링**으로 영상마다 다른 프레임 레이트를 적용한다. 공간 해상도를 이미지 크기에 맞췄듯, **시간 해상도를 영상의 특성에 맞추는 것**이다.

그런데 여기에 문제가 하나 생긴다. 샘플링 레이트가 영상마다 다르면, **모델이 "프레임 한 칸"을 얼마의 시간으로 이해해야 할지 알 수 없다.** 같은 10프레임이 어떤 영상에서는 5초이고 다른 영상에서는 1초일 수 있다.

해결책이 **절대 시간에 정렬된 MRoPE**이다. MRoPE의 시간 성분 ID를 프레임 순번이 아니라 **실제 시간에 대응시킨다.** 그러면 샘플링 레이트가 달라져도 모델이 **일관된 시간 감각**을 갖게 되고, 사건의 순서뿐 아니라 **속도**까지 이해할 수 있다.

그 결과 **몇 시간 길이의 영상**을 다루면서 **초 단위로 사건의 위치를 지목**하는 것이 가능해졌다.

> **참고 — Qwen2-VL의 M-RoPE에서 무엇이 바뀌었나**: Qwen2-VL의 M-RoPE는 시간 성분을 **프레임마다 1씩 증가**시켰다. 프레임 순서는 알 수 있지만 그것이 몇 초인지는 모른다. Qwen2.5-VL은 이 ID를 **절대 시간에 묶어**, 동적 FPS와 결합했을 때도 시간 척도가 흔들리지 않게 했다. **동적 샘플링을 도입하려면 시간 기준점이 먼저 필요했다**는 점에서, 두 변경은 하나의 세트이다.

<br/>

### Window Attention을 도입한 ViT

네이티브 동적 해상도의 대가는 연산량이다. 이미지가 클수록 patch가 많아지고, self-attention은 patch 수에 대해 **제곱으로** 증가한다. 고해상도 문서를 다루려 할수록 이 비용이 급격히 커진다.

Qwen2.5-VL은 ViT를 다시 설계한다.

- **대부분의 레이어에 window attention을 적용**하고, **단 4개 레이어만 full self-attention**을 쓴다. 그 결과 연산량이 patch 수에 대해 **선형**으로 증가한다.
- **RMSNorm과 SwiGLU**를 채택해 Qwen2.5 LLM의 아키텍처와 구성을 맞췄다.
- CLIP이나 DFN 가중치로 초기화하지 않고 **처음부터 학습**했다.

> **참고 — CLIP 인코더로부터의 독립**: [CLIP](clip.md) 이후 대부분의 VLM은 CLIP 계열 인코더를 그대로 가져다 썼다. Qwen2.5-VL이 ViT를 처음부터 학습했다는 것은, **시각 인코더를 LLM에 맞춰 설계할 만큼 데이터와 자원이 충분해졌다**는 신호이다. 정규화 방식과 활성화 함수까지 LLM과 통일한 것도 같은 맥락으로, 두 부분을 별개의 모듈이 아니라 **하나의 모델로 설계**하려는 방향이다.

<br/>

### 학습

- 사전 학습 데이터가 Qwen2-VL의 1.2조 토큰에서 **4.1조 토큰**으로 확대되었다. 이미지 캡션, 교차 배열 문서, OCR, 시각 지식, 학술 QA, localization, 문서 파싱, 비디오 설명, **에이전트 상호작용 데이터**로 구성된다.
- 3단계 사전 학습 이후 **후처리 학습**이 이어진다. 약 200만 건 규모의 **SFT**(절반은 순수 텍스트, 절반은 멀티모달)를 거친 뒤 **DPO**로 정렬한다.
- 모델은 **3B, 7B, 72B** 세 가지로 제공된다.

<br/>

## 실험 결과

- **Qwen2.5-VL-72B는 GPT-4o 및 Claude 3.5 Sonnet과 경쟁하는 성능**을 유지한다.
- **문서와 도표 이해에서 특히 강하다.** DocVQA, InfoVQA, CC-OCR, OmniDocBench 등에서 최상위권을 기록했다. 절대 좌표와 QwenVL HTML, 고해상도 처리가 함께 작용한 결과이다.
- **비디오 이해**에서 Video-MME, LVBench, Charades-STA 등에 걸쳐 강한 성능을 보였다. 특히 **시간적 grounding**을 요구하는 태스크에서의 개선이 두드러진다.
- **에이전트 태스크에서의 성능이 이 버전의 핵심 성과**이다. ScreenSpot, ScreenSpot Pro, Android Control, OSWorld 등 **GUI 조작 벤치마크**에서 우수한 결과를 냈다. 화면을 보고 어디를 눌러야 할지 판단하는 능력이 실제로 측정 가능한 수준에 도달했음을 뜻한다.
- **작은 모델의 실용성**이 크게 개선되었다. 7B가 여러 태스크에서 GPT-4o-mini를 앞서고, **3B가 이전 세대의 7B(Qwen2-VL-7B)를 능가**한다. 엣지 환경 배포가 현실적인 선택지가 되었다.
- **언어 능력이 보존**되었다. 멀티모달 학습 과정에서 순수 언어 성능이 떨어지는 현상이 흔한데, Qwen2.5-VL은 이를 유지했다. SFT 데이터의 절반을 순수 텍스트로 구성한 것이 이에 기여한 것으로 보인다.

<br/>

## 한계점

- **여전히 오디오를 다루지 못한다**: Qwen2-VL과 마찬가지로 비디오 이해가 시각 정보에만 의존한다. 시간 해상도를 정교하게 다듬었음에도 **말소리가 핵심인 영상은 여전히 반쪽만 이해**하는 셈이다.
- **기술 보고서 형식의 한계**: 이 문서는 동료 심사를 거친 논문이 아니라 technical report이다. 각 구성 요소의 기여를 분리해 보여주는 **통제된 ablation이 상대적으로 부족**하다. 예컨대 절대 좌표, window attention, 동적 FPS가 각각 얼마나 기여했는지를 독립적으로 판단하기 어렵다.
- **학습 데이터 비공개**: 가중치는 공개되었지만 4.1조 토큰의 구성은 공개되지 않았다. 벤치마크 오염 여부를 외부에서 검증할 수 없다는 문제가 그대로 남는다. **"오픈 모델"이 가중치의 공개를 뜻할 뿐 재현 가능성을 뜻하지는 않는다.**
- **절대 좌표의 전제 조건**: 절대 좌표는 이미지의 실제 크기를 아는 상황을 전제한다. 리사이즈나 크롭이 개입하는 파이프라인에서는 **좌표계를 일관되게 유지하기 위한 추가적인 관리**가 필요하다.
- **긴 영상의 근본적 제약**: 몇 시간짜리 영상을 다룬다고 해도 결국 토큰 예산 안에서 처리해야 하므로, 길이가 늘어나면 **프레임당 해상도나 샘플링 밀도를 낮추는 타협**이 불가피하다. 동적 FPS는 이 타협을 더 똑똑하게 만든 것이지 없앤 것은 아니다.
- **누적된 미해결 문제**: 복잡한 장면에서의 정확한 개수 세기, hallucination 억제 같은 문제는 세대를 거치며 개선되고는 있으나 해소되지 않았다. 규모와 해상도만으로는 닿지 않는 영역이 있음을 시사한다.

## 인사이트

- **출력 형식이 모델의 쓰임새를 결정한다**: 이 버전의 변화를 관통하는 흐름은 **출력이 문장에서 구조로 바뀌었다**는 것이다. 절대 좌표, JSON, QwenVL HTML, 초 단위 타임스탬프는 모두 **다음 단계 프로그램이 그대로 받아 쓸 수 있는 형식**이다. 사람이 읽는 설명을 잘 쓰는 것과 기계가 파싱할 결과를 내는 것은 다른 능력이며, 후자가 VLM을 파이프라인의 부품으로 만든다.
- **표현이 곧 능력의 상한이다**: 정규화 좌표를 쓰는 한 모델은 객체의 실제 크기를 배울 수 없다. 표현에 담기지 않은 정보는 학습될 수 없기 때문이다. **무엇을 어떻게 표현할지 정하는 것이 모델링의 일부**라는 점을 잘 보여주는 사례이며, 아키텍처 변경 없이 능력을 바꾼 개입이라는 점에서 더욱 그렇다.
- **하나의 원리를 다른 축으로 옮기기**: Qwen2-VL이 공간 축에서 확립한 "입력의 특성에 맞춰 토큰을 배분한다"는 원리를, Qwen2.5-VL은 **시간 축에 그대로 적용**했다. 좋은 원리는 한 번 쓰이고 끝나지 않는다. 다만 그 이식이 성립하려면 **절대 시간 정렬이라는 전제 조건을 함께 마련**해야 했다는 점이, 원리의 이동이 기계적이지 않음을 보여준다.
- **효율이 능력의 전제가 되는 지점**: window attention으로 연산을 선형화한 것은 성능 개선이 아니라 **가능성의 확보**에 가깝다. 제곱 복잡도로는 고해상도 문서를 실용적인 비용으로 다룰 수 없기 때문이다. **효율 개선이 곧 새로운 능력의 문을 여는** 구조이며, 네이티브 해상도 노선이 지속 가능하려면 반드시 거쳐야 할 단계였다.
- **CLIP 인코더 의존에서 벗어나는 흐름**: 시각 인코더를 처음부터 학습하고 정규화·활성화 함수까지 LLM과 통일한 것은, 시각과 언어를 **조립되는 두 모듈이 아니라 하나로 설계되는 모델**로 보는 관점의 전환이다. CLIP → BLIP-2 → LLaVA로 이어진 "기성품 조립" 시대가 성숙 단계에 접어들었다는 신호로 읽을 수 있다.
- **인식 모델과 에이전트의 경계가 사라진다**: GUI 조작 벤치마크에서의 성능을 전면에 내세운 것은 상징적이다. 화면을 보고 정확한 픽셀을 지목해 누른다는 것은 **인식·추론·행동이 하나의 모델 안에서 연결**된다는 뜻이다. 이 저장소의 Agent 카테고리에 있는 GUI 에이전트 연구들과 VLM 연구가 사실상 같은 지점으로 수렴하고 있음을 보여준다.
