## 핵심 아이디어

LLaVA-1.5는 새로운 구조를 제안하지 않는다. 대신 **[LLaVA](llava.md)의 단순한 연결자가 사실은 충분히 강력했으며, 부족했던 것은 몇 가지 사소한 설계와 데이터였다**는 것을 보인다.

LLaVA는 자유로운 대화에 강했지만 학술 벤치마크에서는 [InstructBLIP](instructblip.md) 같은 모델에 밀렸다. 반대로 InstructBLIP은 벤치마크에 강했지만 짧은 답변에 과적합되어 있었다. 당시의 자연스러운 해석은 **"연결자가 단순해서 생긴 한계"** 였고, 따라서 더 정교한 구조가 필요하다는 방향으로 논의가 흘렀다.

LLaVA-1.5는 이 진단이 틀렸다고 말한다. 문제는 연결자가 아니라 **응답 형식에 대한 지시가 없었다는 것, 그리고 학술 태스크 데이터가 없었다는 것**이었다.

세 가지 변경만으로 충분했다.

* **응답 형식 프롬프트** — 짧게 답할지 길게 답할지를 명시적으로 알려준다
* **MLP 연결자** — 선형 레이어 한 장을 2층 MLP로 바꾼다
* **학술 태스크 데이터 추가** — VQA와 OCR 계열 데이터를 섞는다

그 결과 **공개 데이터 120만 개**만으로 **11개 벤치마크에서 SOTA**를 달성했다. 학습은 **A100 8장 한 대에서 하루** 만에 끝난다. 수십억 규모의 데이터를 쓴 모델들을 앞선 결과이다.

## 방법론

### 응답 형식 프롬프트

<!--Figure: Table 1 (Response format prompt ablation)-->

논문에서 가장 통찰이 돋보이는 부분이다.

**문제 진단**: LLaVA는 단답형과 장문형 사이의 균형을 잡지 못했다. 짧게 답해야 할 질문에도 장황하게 답하는 경향이 있었다. 반대로 InstructBLIP은 **짧은 답에 과적합**되어 있었다.

논문은 InstructBLIP의 과적합 원인을 두 가지로 분석한다.

1. **프롬프트가 응답 형식에 대해 모호하다.** `Q: {Question} A:` 같은 형태는 **어떤 길이로 답해야 하는지 아무 단서를 주지 않는다.** 학습 데이터의 정답이 대부분 짧으므로, LLM은 "이 형식으로 물으면 짧게 답한다"고 학습해버린다.
2. **LLM을 학습시키지 않는다.** InstructBLIP은 Q-Former만 학습하므로, **LLM이 출력 길이 행동 자체를 조정할 방법이 없다.** 형식 문제를 데이터로 고치려 해도 고칠 주체가 없는 셈이다.

**해결**: VQA 질문 끝에 **응답 형식을 명시하는 프롬프트 하나**를 붙인다.

> **Answer the question using a single word or phrase.**

이렇게 하면 LLM이 finetuning 과정에서 **"이 지시가 있으면 짧게, 없으면 자연스럽게"** 를 학습한다. 형식은 지시로 통제되고, 모델은 두 모드를 모두 유지한다. ChatGPT로 데이터를 후처리할 필요도 없다.

효과는 컸다. **VQAv2 샘플 약 5만 개를 추가한 것만으로** VQA 벤치마크 성능이 크게 올랐다.

> **참고 — 왜 이 작은 변경이 통했는가**: 문제는 능력이 아니라 **모호성**이었다. 모델은 짧게도 길게도 답할 수 있었지만, 언제 그래야 하는지를 알려주는 신호가 없었기 때문에 데이터의 통계적 경향을 따라가버렸다. 형식을 **지시로 명시화**하는 순간, 두 능력이 충돌하지 않고 공존하게 된다. InstructBLIP이 이 문제를 풀 수 없었던 이유가 **LLM을 얼려두었기 때문**이라는 진단은, frozen 전략의 대가가 어디서 나타나는지를 구체적으로 보여준다.

<br/>

### MLP 연결자

self-supervised learning 분야에서 선형 projection을 MLP로 바꿔 성능을 개선한 사례에 착안하여, **선형 레이어 한 장을 2층 MLP로 교체**했다.

변화는 최소한이지만 개선은 일관되게 나타났다. 여전히 Q-Former 같은 정교한 구조와는 거리가 멀며, **"조금 더 표현력 있는 사영"** 이상의 것을 하지 않는다.

<br/>

### 학술 태스크 데이터

LLaVA의 158K 데이터는 GPT-4가 생성한 대화 중심이라, 특정 능력이 통째로 비어 있었다. 이를 메우기 위해 데이터를 추가한다.

- **Open-knowledge VQA**: OKVQA, A-OKVQA — 외부 지식이 필요한 질문
- **OCR 계열**: OCRVQA, TextCaps — 이미지 속 글자 인식
- **GQA**: 추가적인 시각 지식
- **ShareGPT**: 텍스트 전용 대화 데이터

A-OKVQA는 객관식으로 변환하고 응답 형식 프롬프트를 붙였다. 각 데이터셋의 **일부만 써도 충분**했다.

<br/>

### 해상도 확장

- 이미지 인코더를 **CLIP ViT-L/14 @ 336px**로 올렸다(기존 224px). 해상도가 곧 인식 가능한 디테일의 상한이므로, 특히 OCR 계열에서 효과가 크다.
- 여기서 더 나아가 **이미지를 격자로 나눠 각 조각을 독립적으로 인코딩한 뒤 합치는 방식**으로 448까지 확장했다. 인코더를 다시 학습시키지 않고 해상도를 올리는 방법으로, 이후 **타일링 기반 고해상도 처리의 원형**이 된다.

<br/>

### 최종 구성

- **Vision Encoder**: CLIP ViT-L/14 @ 336px
- **Connector**: 2층 MLP
- **LLM**: Vicuna v1.5 (13B)
- **데이터**: 사전 학습 558K + **instruction tuning 665K**
- **학습 비용**: A100 8장 **약 1일**

<br/>

## 실험 결과

### 벤치마크 성능

<!--Figure: Table 2 (Comparison with SOTA methods on 12 benchmarks)-->

- **12개 벤치마크 중 11개에서 SOTA**를 달성했다. VQAv2, GQA, VizWiz, ScienceQA, TextVQA, POPE, MME, MMBench, SEED-Bench, LLaVA-Bench-Wild, MM-Vet 등 이해와 대화를 아우르는 범위이다.
- **데이터 규모의 대비가 극적이다.** Qwen-VL이 14억 규모의 데이터를 쓴 반면 LLaVA-1.5는 **120만 개의 공개 데이터**만 사용했다. 그럼에도 앞섰다.
- InstructBLIP을 벤치마크에서 앞서면서, **동시에 개방형 대화 능력도 유지**했다. 두 진영의 장점이 배타적이지 않음을 보인 것이다.

<br/>

### 데이터 효율성

665K 혼합 데이터를 **무작위로 절반만 남겨도 성능의 98% 이상이 유지**되었다.

이는 현재의 데이터 구성에 상당한 중복이 있으며, **더 효율적인 학습이 가능하다**는 것을 시사한다. 데이터의 양보다 **어떤 능력을 커버하는지**가 중요하다는 관점을 뒷받침하는 결과이기도 하다.

<br/>

### 능력의 합성적 전이

논문이 관찰한 흥미로운 현상들이다.

- **텍스트 전용 데이터가 멀티모달 능력을 개선한다.** ShareGPT 같은 언어 데이터를 섞으면 멀티모달 성능이 올라간다.
- **모달리티 경계를 넘는 일반화가 나타난다.** LLaVA-1.5는 **중국어 멀티모달 데이터로 학습한 적이 없는데도 중국어로 답할 수 있다.** 언어 데이터에 포함된 중국어 능력과, 영어 멀티모달 데이터로 학습한 시각 이해 능력이 **결합**된 결과이다.
- **학습에서 보지 못한 형식 지시도 따른다.** VizWiz의 "답할 수 없음" 처리처럼 새로운 형식 요구에 대응했다.

여러 능력을 함께 학습시키면 **각각의 합보다 큰 결과**가 나온다는 것이 이 절의 요지이다.

<br/>

### Hallucination

POPE 벤치마크에서 LLaVA-1.5는 InstructBLIP을 비롯한 기존 모델들보다 **hallucination이 적었다.**

논문은 그 원인을 데이터에서 찾는다. **길고 상세한 캡션으로 학습한 모델일수록 hallucination이 많은 경향**이 있는데, 그런 캡션 자체에 이미 부정확한 내용이 섞여 있기 때문이다. 학습 데이터의 hallucination이 모델의 hallucination으로 이어진다는, 단순하지만 중요한 상관관계이다.

<br/>

## 한계점

- **전체 이미지 패치를 그대로 사용**: 시각 토큰을 압축하지 않으므로 학습 반복마다 시퀀스가 길어지고 시간이 늘어난다. 논문은 Q-Former 같은 **visual resampler가 토큰 수를 줄여주지만, 동일한 데이터 양에서는 LLaVA만큼 효율적으로 수렴하지 못한다**고 지적한다. resampler의 학습 파라미터가 더 많은 것이 원인으로 추정되며, **샘플 효율이 좋은 resampler**를 향후 과제로 남긴다.
- **다중 이미지를 처리하지 못함**: 여러 장을 다루는 instruction 데이터가 없고 컨텍스트 길이에도 제약이 있어, 이미지 간 비교나 관계 추론이 불가능하다.
- **특정 도메인의 문제 해결 능력 부족**: 전문 지식이 필요한 영역에서는 여전히 약하며, 논문은 더 강한 LLM과 해당 도메인의 고품질 데이터로 개선할 수 있다고 본다.
- **Hallucination이 사라진 것은 아님**: POPE에서 상대적으로 나을 뿐이며, 논문은 **의료처럼 중요한 응용에서는 주의해서 사용해야 한다**고 명시한다.
- **해상도의 근본적 제약**: 336px, 격자 방식으로 448px까지 올렸지만 여전히 낮다. 조밀한 문서나 작은 글자를 다루기에는 부족하며, 격자 분할은 **조각 간의 맥락이 끊긴다는 부작용**도 있다.
- **벤치마크 중심 평가의 한계**: 11개 벤치마크 SOTA가 실사용 품질을 그대로 보장하지는 않는다. 응답 형식 프롬프트가 벤치마크의 단답 요구에 정확히 부합한다는 점에서, **평가 형식에 맞춘 최적화**라는 측면도 함께 봐야 한다.

<br/>

## 인사이트

- **복잡한 구조가 필요하다는 진단이 틀렸다**: LLaVA가 벤치마크에서 밀린 이유는 연결자가 단순해서가 아니라 **데이터와 프롬프트 설계 때문**이었다. 선형 레이어를 2층 MLP로 바꾸는 최소한의 변경과 적절한 데이터만으로 정교한 구조들을 앞섰다는 사실은, **성능 격차의 원인을 아키텍처에서 찾는 습관을 경계하게 만든다.** 원인을 잘못 짚으면 불필요한 복잡성만 쌓인다.
- **작은 개입이 큰 트레이드오프를 해소한다**: 단답형과 장문형의 균형은 당시 구조적 딜레마로 여겨졌지만, 실제로는 **형식을 지시로 명시하는 한 문장**으로 풀렸다. 모델이 두 능력을 다 갖고 있는데 언제 쓸지 모르는 상황이라면, 능력을 키울 게 아니라 **신호를 주는 것이 답**이다.
- **frozen 전략의 대가가 드러난 지점**: InstructBLIP이 짧은 답변 편향을 고치지 못한 이유를 **LLM을 얼려두었기 때문**으로 진단한 대목은 중요하다. frozen은 catastrophic forgetting을 막고 효율을 주지만, 그 대가로 **LLM 자체의 행동을 교정할 수단을 잃는다.** 무엇을 얼릴지는 효율의 문제가 아니라 **어떤 종류의 문제를 고칠 수 있는가의 문제**이다.
- **능력은 모달리티 경계를 넘어 합성된다**: 중국어 멀티모달 데이터 없이 중국어로 답하고, 텍스트 전용 데이터가 멀티모달 성능을 올린다는 관찰은, 학습된 능력들이 **독립적으로 쌓이는 것이 아니라 결합**됨을 보여준다. 데이터 구성을 태스크별 커버리지가 아니라 **능력의 조합**으로 사고해야 하는 이유이다.
- **재현 가능한 베이스라인이 만든 파급력**: 공개 데이터 120만 개와 A100 8장 하루라는 조건은, 누구나 검증하고 변형할 수 있다는 뜻이다. LLaVA-1.5가 이후 수많은 연구의 **사실상 표준 베이스라인**이 된 것은 성능만이 아니라 이 접근성 때문이다. **재현 가능성 자체가 영향력의 구성 요소**임을 보여준다.
- **고해상도 처리의 출발점**: 이미지를 격자로 나눠 인코딩하는 방식은 인코더를 다시 학습시키지 않고 해상도를 올리는 실용적 타협이었고, 이는 LLaVA-NeXT의 AnyRes로, 나아가 Qwen2-VL과 InternVL의 **동적 해상도** 접근으로 이어진다. 해상도가 VLM의 다음 병목이라는 인식이 여기서 구체화되었다.
